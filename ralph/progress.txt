## Codebase Patterns
- Branch for this PRD: `ralph/canvas-extraction` (created from main)
- Monorepo workspaces: `apps/*` + `packages/*` declared in root package.json; canvas package is `@seeflow/canvas` consumed via `workspace:*`
- Canvas package layout: `packages/canvas/src/{index.ts, types.ts, lib/}` — barrel re-exports go in `src/index.ts`, scaffold already extracts shared schema types + color tokens + icon registry
- Type imports inside @seeflow/canvas use `.ts` extensions (e.g. `from './types.ts'`); follow the existing convention when adding new exports
- Plain `@types/*` packages live in `devDependencies` for canvas, but apps/web historically kept some `@types/*` in `dependencies` — match the existing block in each package.json
- When canvas package needs a runtime dep that apps/web already lists (e.g. `clsx`, `tailwind-merge`), add it to `peerDependencies` in `packages/canvas/package.json` (matches the US-006 pattern for `@xyflow/react`). bun workspace hoisting resolves it via apps/web. Later P2/P3 stories may upgrade these to full `dependencies` and remove them from apps/web.
- When promoting a canvas peerDependency to a real `dependency` (US-011 pattern): remove the entry from `peerDependencies`, add the same package+version to `dependencies`, then remove the corresponding line from `apps/web/package.json`. bun install resolves transitively from canvas. apps/web files that didn't import the package directly need no other changes — workspace hoisting just works.
- Re-exporting an entire submodule barrel (US-011 pattern): `export * from './ui/index.ts';` at the bottom of `packages/canvas/src/index.ts` is the cleanest way to expose all primitives. The submodule's own index.ts uses explicit named re-exports (`export { Button } from './button.tsx';`) — this preserves tree-shaking while keeping the top-level barrel concise.
- Biome's `useImportType` rule does NOT auto-merge duplicate imports from the same module — after a bulk path-swap that produces two `from '@seeflow/canvas'` lines in the same file, manually splice the new symbol into the existing import block (alphabetical) instead of waiting for `biome check --fix` to fix it
- `bun run lint` (Biome) is import-order strict; running `bunx @biomejs/biome check --fix <file>` is the safe way to resolve `organizeImports` errors
- Always run `bun run format` before `bun run lint` per CLAUDE.md
- Quality gate per Ralph CLAUDE.md: `bun run typecheck`, `bun test`, `bun run format`, `bun run lint`
- Canvas package's tsconfig only includes `["bun", "react"]` types — when adding a `.test.ts` file under `packages/canvas/src`, no extra changes are needed (`bun:test` resolves via the `bun` types entry added in US-002). `@types/bun` is in the canvas devDependencies.
- When moving a util into @seeflow/canvas: copy file → create test alongside with `from './<name>'` self-import → add re-export block (values + types separately) at the bottom of `packages/canvas/src/index.ts` using `.ts` extensions → update web import sites to `@seeflow/canvas` → delete originals → run `bunx @biomejs/biome check --fix <changed web files>` to fix import order before lint.
- `@xyflow/react` is now a peerDependency of `@seeflow/canvas` (added in US-006). bun install auto-populates `packages/canvas/node_modules/@xyflow/react` so canvas tests resolve it. Any future-moved file that imports from `@xyflow/react` will work without further package.json changes.
- Studio dev mode (`bun run dev`) proxies "/" → vite at hardcoded `http://localhost:5173` (see `apps/studio/src/server.ts` `DEFAULT_VITE_DEV_URL`); apps/web vite is `strictPort: true`. If port 5173 is already in use, use the prod-bundle smoke-test path instead: `cd apps/web && bun run build` (outputs to `apps/studio/dist/web/`), then `NODE_ENV=production bun run --filter @tuongaz/seeflow start`. `apps/studio/dist/web/` is tracked in git — `git checkout HEAD -- apps/studio/dist/web` to restore after the build overwrites it.
- Studio API: `GET /api/demos` lists registered demos; `GET /d/<slug>` is the canvas page route. SSE endpoint `/api/events?demoId=…` produces `ERR_INCOMPLETE_CHUNKED_ENCODING` console errors on demo switch — these are normal connection aborts, not regressions.
- Promoting a literal-union type from apps/web/src/lib/api.ts into @seeflow/canvas (US-012 pattern for `StatusReportState`): add the type literal to `packages/canvas/src/types.ts`, re-export from `packages/canvas/src/index.ts`, then change api.ts to `import + export type { X } from '@seeflow/canvas'` and delete its own definition. The dozens of `from '@/lib/api'` importers keep working unchanged — single source of truth without a cross-codebase rename. The wrapping interface (e.g. `StatusReport`) can stay in api.ts until its own story; canvas only needs the leaf literal.
- Depth rule for files moved under `packages/canvas/src/nodes/`: `@/lib/api` type imports → `'../types.ts'`; for files inside `packages/canvas/src/nodes/shapes/`, it's `'../../types.ts'`. Sibling-file imports inside `nodes/shapes/` use `'./<name>.tsx'`.
- Nested-barrel pattern (US-012's `nodes/shapes/` inside `nodes/`): each leaf barrel uses explicit named re-exports; each parent barrel does `export * from './sub/index.ts'`. The top-level `packages/canvas/src/index.ts` then needs only one line per top-level submodule. Tree-shaking is preserved by the explicit named re-exports at the leaves.
- When moving a component whose private dep chain is unrelated to the canvas (e.g. html-node's use-html-content → file-watch-bus chain in US-013): grep every helper to confirm it's only used by the component being moved, then move the whole chain into `packages/canvas/src/lib/`. The "AC forbids `@/` imports in the moved file" constraint forces the chain decision; deferring is not an option once the component move is mandated. Helpers that touch SSE / project URLs (file-watch-bus' `/api/events`) are fine inside canvas — they're just URL strings, not app code.
- When promoting a runtime *interface* (not just a literal union) from `apps/web/src/lib/api.ts` into canvas (US-013 for `StatusReport`): same pattern as US-012 for `StatusReportState` — add the interface to `packages/canvas/src/types.ts`, re-export from `packages/canvas/src/index.ts`, then change api.ts to `import + export type { X } from '@seeflow/canvas'` and delete its own definition. Interfaces that reference an already-promoted literal can be moved any time their first canvas-side consumer appears.
- happy-dom is a canvas devDependency as of US-013 (added for sanitize-html.test.ts + html-node.test.tsx). Future canvas tests that need a DOM (`DOMParser`, `document`, real Element APIs) install the happy-dom Window's globals before importing the module-under-test, same pattern that's been used in apps/web tests for ages.
- For the `import type {...}` block at the top of `apps/web/src/lib/api.ts`: even when a type is only re-exported (never used in the file body), keep it in the `import type {...}` block — Biome and TypeScript both allow this, and removing the import line by line risks breaking the `export type {...}` re-export when a future story re-uses the symbol in the file body. The block is the source of truth for what api.ts mirrors from canvas.

Do NOT route through the barrel (`from '@seeflow/canvas'`) — that creates a self-import cycle. Same sibling-file anti-cycle pattern that US-010/US-014/US-017/US-018 used for `cn`, `InlineEdit`, `ICON_DEFAULT_SIZE`, etc.
- When a canvas helper has app-scoped state (e.g. `last-used-style`'s localStorage key, US-019), parameterize the namespace via a required `prefix: string` first argument and export a `DEFAULT_STORAGE_PREFIX` constant. Apps/web passes `DEFAULT_STORAGE_PREFIX` at every call site to reproduce the legacy key — embedders pass their own prefix to scope their storage. The same pattern can apply to any future canvas helper that reaches into a shared global (localStorage, sessionStorage, indexedDB, custom DOM events). Make `prefix` REQUIRED (not optional with a default) so callers can't silently fall back to the canvas's preferred namespace.
