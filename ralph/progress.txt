## Codebase Patterns
- Studio sources live in `apps/studio/src/` with co-located `*.test.ts` (Bun test). Run a single file with `bun test apps/studio/src/foo.test.ts` from repo root.
- Pub/sub modules follow the `createX(deps)` factory pattern (see `events.ts`): closure-captured state, `subscribe(fn)` returns an unsubscribe closure, throwing subscribers are caught + logged without affecting others.
- Quality gate order: `bun run format` (biome --write) → `bun run lint` (biome check) → `bun run typecheck` (fans out via concurrently).
- Typecheck needs `@seeflow/canvas` built first (`cd packages/canvas && bun run build`) because schema.ts imports `@seeflow/canvas/catalog` types from its dist.
- Biome strict on unused variables — use `// biome-ignore lint/correctness/noUnusedVariables: <reason>` when reserving a slot for an upcoming story.
- `noUncheckedIndexedAccess` is on — array access returns `T | undefined`; use optional chaining or guards.

## 2026-05-31 - US-016
- Added `apps/studio/src/share-transport.ts`: `createShareTransport(opts)` returning `{ send, close, isOpen }`. Connects synchronously via injectable `wsFactory` (defaulting to Bun's global `WebSocket`), emits state through `onStateChange` ('connecting' | 'open' | 'reconnecting' | 'closed'), sends the `auth-host` envelope as the first frame after `open`, parses inbound text frames via `parseEnvelope` (drops invalid + logs only the reason), reconnects on non-1000 close with exponential backoff (500ms → 30s cap, +/- 20% jitter), and suppresses reconnects after `close('user')` (1000).
- Injected `setTimeoutFn`/`clearTimeoutFn`/`random` so tests can drive the scheduler synchronously without real time.
- Added `apps/studio/src/share-transport.test.ts` with 7 cases using an in-memory `FakeWebSocket`: auth-host first-frame contract, valid frame dispatch, three flavors of invalid frame dropped, reconnect after abnormal close (initial 500ms with zero-jitter random=0.5), user-close suppresses reconnect, send() throws when not open, backoff doubles to 1000ms on repeated reconnects.
- Files changed: `apps/studio/src/share-transport.ts` (new), `apps/studio/src/share-transport.test.ts` (new), `ralph/prd.json` (US-016 passes=true), `ralph/progress.txt`.
- Quality: `bun test` across the three share files → 22/22 pass; `bun run format`, `bun run lint`, `bun run typecheck` all clean.
- **Learnings for future iterations:**
  - `WebSocketLike` is a deliberately narrow shape (addEventListener/removeEventListener/send/close/readyState only) so tests can swap in a `FakeWebSocket` without inheriting from the global. Bun's `WebSocket` satisfies it via a single `as unknown as WebSocketLike` cast in `defaultWsFactory` — no DOM lib needed.
  - State equality check pattern: initialize `currentState` to `null` (not the first real state) so the inaugural `setState('connecting')` actually fires; otherwise the first listener push gets swallowed and tests of the initial state see `[]`.
  - For deterministic backoff tests, inject `random: () => 0.5` — the formula `base + base*0.2*(rand*2-1)` collapses jitter to zero at 0.5 so you can assert exact ms values.
  - Bun's `bun:test` doesn't ship fake timers; the `setTimeoutFn`/`clearTimeoutFn` injection pattern (with a cancellable `{ fn, ms, cancelled }` queue in the harness) gives you full synchronous control over reconnect scheduling. Reusable for any timer-driven module.
  - After abnormal close, the reconnect helper sets state to `'reconnecting'` BEFORE the timer fires, then `connect()` checks `currentState === 'reconnecting'` to avoid bouncing back to `'connecting'`. That means the listener sequence on a single reconnect is `open → reconnecting` (not `open → reconnecting → connecting`).

- **Learnings for future iterations:**
  - The 14 envelope `type` strings live in two places now — keep `ENVELOPE_TYPES` in share-envelope.ts in sync with the relay-side enum when phase 1 (relay) lands. The acceptance criteria list in US-015 is the canonical order.
