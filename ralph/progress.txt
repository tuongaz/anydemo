- Branch for this PRD: `ralph/canvas-extraction` (created from main)

- Canvas package layout: `packages/canvas/src/{index.ts, types.ts, lib/}` — barrel re-exports go in `src/index.ts`, scaffold already extracts shared schema types + color tokens + icon registry

- Re-exporting an entire submodule barrel (US-011 pattern): `export * from './ui/index.ts';` at the bottom of `packages/canvas/src/index.ts` is the cleanest way to expose all primitives. The submodule's own index.ts uses explicit named re-exports (`export { Button } from './button.tsx';`) — this preserves tree-shaking while keeping the top-level barrel concise.

In tests, define the function untyped (or with the explicit signature) and cast: `const impl = fn as unknown as typeof fetch;`. Never put this cast in product code — adapter consumers see the proper Web API `fetch` shape.
- Browser smoke-test reliability rules (US-023, repeatable in US-033): (a) for modifier-key interactions, use `browser_press_key('Meta+a')` + `browser_click` — NOT `document.dispatchEvent(new MouseEvent(..., { shiftKey: true }))` (React Flow throws internal `TypeError: Cannot read properties of null (reading 'document')` because the synthetic event's currentTarget isn't a real React Flow node target); (b) toolbar button aria-labels are NOT always shorthand — they often include the keyboard hint suffix (`Database (D)`, `Rectangle (R)`, `Tidy layout (⌘⇧L)`) or a different verb (`Insert icon` not `Icon`) — enumerate first via `Array.from(document.querySelectorAll('button')).map(b => b.getAttribute('aria-label'))` rather than guessing; (c) StyleStrip color swatch aria-labels are `border color <name>` and `fill <name>` (well-formed for `button[aria-label]` lookups); (d) for last-used-style verification, the legacy localStorage key shape is `seeflow:last-used-style:v1` with value `{"node":{...},"connector":{...}}` — set `localStorage.removeItem(...)` before the click, then re-read after.
- CanvasAdapter wiring (US-025): demo-canvas.tsx accepts `adapter: CanvasAdapter` as a required prop but doesn't yet consume it internally — every mutation site lives in `apps/web/src/pages/demo-view.tsx`, which constructs the adapter via `const adapter = useMemo(() => demoId ? createRestAdapter({ baseUrl: '', demoId }) : null, [demoId])`. REST calls were swapped via mechanical `<fn>(demoId, ` → `adapter.<fn>(` replace_all per method (9 patterns, ~100 callsites total). Early-return guards: `if (!demoId)` → `if (!demoId || !adapter)` (TS can't auto-correlate the two). JSX render gate: `{demo && adapter ? <DemoCanvas adapter={adapter} ...> : <fallback>}` narrows adapter inside the children. The image-upload-flow.ts orchestrator still uses legacy (demoId, …) deps signatures — wrap the adapter inline at the callsite with `(_projectId, file, filename) => adapter.uploadImage(file, filename)` etc.; refactoring image-upload-flow's signature is a later story.
- For correlated `string|null` + `T|null` variables built via `useMemo(() => x ? makeY(x) : null, [x])`: TypeScript can't auto-narrow Y when x is checked, even though they're logically the same lifecycle. The cheapest fix is the combined check `if (!x || !y) return;` which narrows both. Don't reach for `!` assertions or double-guards — the combined check is the readable canonical form for this pattern. Same applies in JSX gates: `{x && y ? <Comp x={x} y={y} /> : ...}`.
- When mechanically replacing in deps arrays via `replace_all`, watch the spacing: `[demoId, ` (trailing space) → `[demoId, adapter, ` produces a missing-space artifact unless the replacement also ends with a trailing space. Either include the trailing space in BOTH old and new strings, OR drop it from both and immediately run `bun run format` so biome inserts the canonical single-space-after-comma. For multi-line deps arrays, use Edit with literal 2-line old/new strings (`      demoId,\n      <nextDep>,` → `      demoId,\n      adapter,\n      <nextDep>,`) — unambiguous and order-preserving.
- For test files that need to satisfy a "this prop is required" type constraint without exercising the prop, use a throwing `noopAdapter` Proxy: `new Proxy({} as CanvasAdapter, { get: (_t, key) => () => { throw new Error(\`adapter.\${String(key)} should not be invoked in unit tests\`); } })`. Catches future drift where a test inadvertently triggers an adapter call instead of silently returning undefined and corrupting downstream state.
- Bundling multiple per-stream props into one runtime object (US-026 pattern): when consolidating N individual props (`runs`, `statusByNode`, `nodeOverrides`, `connectorOverrides`) into a single `runtime?: CanvasRuntime` prop, do a 4-line destructure at the TOP of the function body — `const runs = runtime?.runs; const statusByNode = runtime?.statuses; const nodeOverrides = runtime?.pendingOverrides?.nodes; const connectorOverrides = runtime?.pendingOverrides?.connectors;` — so every downstream useMemo / deps array / read site stays byte-identical. The diff for the prop API is ~30 lines; the function body needs no other changes. Same pattern applies any time you're collapsing related props into a container object: keep the legacy NAMES in scope as local aliases.
- For legacy test convenience after a prop API change (US-026 pattern): widen the test builder's parameter type to `LegacyOverrides = Partial<NewProps> & { legacyFieldA?: ...; legacyFieldB?: ... }`, then inside the builder LIFT the legacy fields into the new shape before constructing the actual props object. Tests stay unchanged; production code uses the new API only. Avoids a wave of mechanical test rewrites for every test site that passes one of the old prop names. Mirror update: if a helper function (`findOverlay` etc.) types its arg as `Partial<NewProps>`, widen to `LegacyOverrides` too — same one-line change.
- Avoiding hook-file imports in canvas-side type signatures (US-026 pattern): when a helper used by demo-canvas was typed as `(runs: NodeRuns | undefined, …)` where `NodeRuns` came from `@/hooks/use-node-runs`, retype to a canvas-anchored alias: `type RunsMap = CanvasRuntime['runs']`. The alias is a derived type from the adapter-side `CanvasRuntime`, so the helper doesn't import from `@/hooks/*` anymore — and the AC's "no `useNodeRuns` import" rule is satisfied even for transitive type imports.
- Discriminated-union prop refactor (US-027 pattern): when a prop's required-ness flips with a discriminator (mode='edit' requires `adapter: CanvasAdapter`; mode='view' makes it optional), extract every shared prop into a private `interface FooBaseProps` and define `export type FooProps = (FooBaseProps & { mode: 'edit'; required: T }) | (FooBaseProps & { mode: 'view'; required?: T })`. Inside the function, destructure `mode` + the discriminated field + the base props in a single statement: `const { mode, adapter, ...rest } = props`. `Partial<Union>` distributes to `Partial<A> | Partial<B>`, so test override types like `Partial<FooProps>` keep working unchanged — just default `mode: 'edit'` in the test builder so legacy assertions continue to hold.
- resolveFlags helper shape (US-027 pattern): mode preset + per-feature overrides → concrete flag set. Keep the helper PURE and decouple it from the host component's other props (only takes `{ mode } & FeatureOverrides`) so it's trivially unit-testable. Use `input.foo ?? defaults.foo` for every flag — never `||` or `Boolean(input.foo)` — so an explicit `false` override beats an edit-true preset and `undefined` correctly falls back to the preset. Two `XXX_DEFAULTS: ResolvedFlags` constants (one per mode) make the policy locally readable. View mode keeps `enableZoom`/`enablePan`/`showStatusBadges` true so the canvas remains a useful navigable presentation surface even with editing disabled.
- Gating layered chrome + behavior on resolved flags (US-027 pattern): always defense-in-depth. Gate at THREE layers for any view-mode-suppressed behavior: (1) the JSX render site (`{flags.showToolbar && onCreateShapeNode ? <Toolbar /> : null}`); (2) the ReactFlow prop wire (`nodesConnectable={isEditMode && !!onCreateConnector}`); (3) the handler body itself (`if (!isEditMode) return;` at the top of onConnect / commitDraggedNodes / etc.). The render layer hides the affordance, the prop wire prevents xyflow from initiating the gesture, the body gate is the defensive net if the prop wire is bypassed by an embedder mistake. Same applies to context menus — gate the onNodeContextMenu wiring AND the ContextMenu render AND the handler bodies.
- xyflow doesn't have a global `edgesDeletable` flag (it's per-edge: `edge.deletable: boolean` defaults true). To globally disable keyboard delete from the canvas root, use `deleteKeyCode={null}`. Don't reach for a per-edge override loop — it would churn edge identity through every render and break the rfEdges useMemo cache. The keyboard-chord disable is sufficient because the context menu's Delete item is already gated separately on `flags.enableContextMenu`.
- Empty-deps useCallback that needs to read a derived value (US-027 pattern): mirror the value into a ref. `const flagsRef = useRef(flags); useEffect(() => { flagsRef.current = flags; }, [flags]);` then read `flagsRef.current.flagName` inside the callback. Avoids re-binding the callback every render while still reading the live value. Same pattern used for the connecting/dropPopover/selectedIdSet refs elsewhere in demo-canvas. Note: adding a new useRef shifts the index of every existing useRef — search the test file for any `refSink[N]` / REF.* enum and bump them. The REF enum in demo-canvas.test.tsx has an in-comment changelog tracking these shifts.
- Browser smoke-test "no PATCH on drag" verification (US-027 pattern): the most reliable assertion for "view mode doesn't persist" is checking the network panel. After dispatching a node drag (via `browser_evaluate` synthetic pointer events or Playwright's native browser_drag), call `browser_network_requests({ filter: '/api/demos/.+(nodes|connectors|position)' })` — empty result == zero mutations. Don't try to assert on the visual translate() — synthetic pointer events don't always reliably trip d3-drag's threshold inside React Flow's wrapper, but the unit test (commitDraggedNodes early-return) pins the local-state-only behavior, and the network assertion pins the no-persistence side.

Use `[[:<:]]` for start-of-word and `[[:>:]]` for end-of-word: `sed -i '' 's/[[:<:]]DemoCanvas/SeeflowCanvas/g' file.ts`.   - When a barrel relocation is purely additive at the consumer side (1 new symbol `SeeflowCanvas` + 1 newly-routed-through-barrel symbol `createRestAdapter`), demo-view.tsx's import block consolidation is a single Edit: drop the 2 old `@/` lines, splice 3 symbols into the existing `@seeflow/canvas` block, let biome auto-fix sort. The pattern generalizes to any future canvas-side promotion (move N symbols from apps/web to canvas in story A; demo-view consumes them via the existing barrel block in story B with the same single-Edit pattern).
  - `apps/studio/dist/web/` is a tracked artifact built by `apps/web && bun run build`. After every prod-bundle smoke test, run `git checkout HEAD -- apps/studio/dist/web` to restore the previous hashed asset names, then `rm` any new untracked files in `apps/studio/dist/web/assets/`. The build does NOT delete old assets; it only appends new hash-named ones, so the untracked-file cleanup is mandatory.

If only (a) holds, the class is present in markup but the stylesheet is missing it — that's the regression Tailwind content paths are meant to prevent.
