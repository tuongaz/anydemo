    required field to the `active` variant cascades to every test that
    builds an `active` literal. Run a quick `grep -n "status: 'active'"
    apps/studio/src/*.test.ts` after such changes.

    tampered peer adding extra fields under `attributedTo`; passthrough on
    the outer payload preserves the deliberate looseness around `diff`
    (already `z.record(z.unknown())` per existing schema design).

    `(frame, fromPeerId)` to `(frame, {peerId, displayName})` would break
    the public `handleRpcFrame` API and all existing tests. Instead, kept
    the public API stable (added optional `displayName` 3rd arg) and only
    refactored the *internal* helper — public/internal divergence is fine
    here since the internal call site (handleFrame) is the only producer
    of the structured actor.
  - **Cross-validation that needs runtime context** (e.g. `attributedTo.peerId
    === 'host' OR ∈ knownPeers`) can't be expressed in a Zod schema without
    a refinement closure that captures the set. The AC's "matching a known
    peer" constraint is enforced implicitly at the broadcast site (the host
    can only attribute to peers it knows about via connPeers) — no schema
    refinement needed.

    `RpcAuditEntry` is safe (per-line JSONL, no header), and existing
    consumers reading older lines see the field as `undefined`. Don't make
    new audit fields required without a version bump.

    accepted op (peer rpc AND `broadcastHostEdit`). To add a side-effect
    that fires per accepted op (audit, attribution, metrics, etc.), hook
    it INSIDE this helper — not at the call sites — so peer + host paths
    can never diverge. The helper takes attribution as an arg, so the
    side-effect has full attribution context for free.

    `() => void | (() => void)` because `void` in a union is confusing

    useEffect callbacks for manual invocation.

- **Learnings for future iterations:**
  - **Bun's test runtime does NOT expose `window` / `sessionStorage` even
    for `.tsx` test files** — there's no DOM shim in seeflow-viewer's
    bunfig.toml (file doesn't exist). For a test that exercises a
    sessionStorage-backed module, install an in-memory `Storage` stub on
    `globalThis.window` at the top of the test file and restore in
    `afterAll`. The pattern: `class MemoryStorage implements Storage { ... }`
    plus `(globalThis as { window: { sessionStorage: Storage } }).window =
    { sessionStorage: storage }`. This is cheaper than adding a real
    happy-dom preload.
  - **Cloud `CursorPayloadSchema` permits extra fields** — Zod's default
    `strip` mode silently drops unknown keys at the parse boundary, but the
    relay's `routeFrame` forwards `event.body` unchanged on broadcast (not
    the parsed payload). So adding `color?: string` to outgoing cursor
    payloads requires no cloud schema edit — the field rides through to
    remote peers as-is. The viewer-side `CursorPayloadSchema` in
    presence-store DOES need the field added so re-validation on receipt
    doesn't drop it from the typed result. Tests confirm: 199 pass on the
    viewer suite with the color field, cloud suite untouched.
  - **Self color matches relay color via SHA-256 mirror.** Cloud relay's
    `colorForPeerId` reads `digest.readUInt32BE(0) % 360` for hue.
    `derivePeerColor` in viewer must use `view.getUint32(0, false)` (false =
    big-endian) for byte-for-byte parity. Mixing this up produces a hue
    that differs by exactly the byte-swap, which is visible as a noticeable
    color shift when the placeholder gets overwritten by the relay-derived
    presence frame. Always verify the byte order against the server when
    mirroring crypto-derived values client-side.
  - **`hostDisplayName` default change cascades to existing tests.** The
    pre-existing `'ShareState hostDisplayName default'` test in
    `share.test.ts` asserted `'Host'` — once the default flipped to
    `resolveHostDisplayName()`, that test needed an explicit dep override
    to keep asserting the literal. Pattern: when changing a `??`-style
    default in a controller factory, grep `*.test.ts` for the old default
    string and update the assertions.
  - **`useEffect` deps and stale closure capture:** `share-session.tsx`'s
    main effect captures `cachedIdentity` + `token` from useMemo/useParams,
    but its dep array is `[joinedData]`. Biome doesn't enforce
    exhaustive-deps so this passes lint, and in practice `cachedIdentity`
    is stable per-token (useMemo with `[token]`), so the closure capture is
    OK. A token change triggers a re-mount via the router, which resets
    everything. If a future change splits these dependencies, audit the
    effect for stale `cachedIdentity` reads.
