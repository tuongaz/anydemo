## Codebase Patterns
- `packages/canvas/src/index.ts` is the only public barrel — add new exports under the matching numbered section and keep it sorted (5 → 5b → 5c → 6 …).
- Biome's `organizeImports` enforces alphabetical order on import groups; sort sibling type-only imports by source path or the lint fails. Value imports come BEFORE type imports from the same path family.
- `bun test <path>` only works from the repo root (the bun-test cwd-filter trips up nested paths in `apps/*` / `packages/*`).
- Adapter-layer types live in `packages/canvas/src/adapter/`. The canonical adapter shape is `CanvasAdapter` (throw-on-error); a non-throwing twin (`IoAdapter`) sits in a sibling file and is wrapped at the SeeflowCanvas prop boundary — never imported from the rendering layer.
- `bun run format` MUST run before `bun run lint` — Biome only emits fixes when `--write` runs, and `lint` is the gate.
- `apps/studio/src/server.test.ts` and `apps/studio/src/watcher.test.ts` have pre-existing flakiness (timeouts under parallel load and timing-sensitive fs-watcher assertions) that is independent of canvas-side work. Canvas-only changes only need canvas-suite green.
- `Partial<SeeflowCanvasProps>` cannot be spread into a typed `SeeflowCanvasProps` literal once the union has overlapping mode arms — the test helper casts via `as unknown as SeeflowCanvasProps` to bypass arm-by-arm narrowing.
- Files that are byte-for-byte mirrored across the seeflow + seeflow-viewer repos MUST be self-contained — no imports from sibling modules that don't exist on both sides (e.g. operations.ts is studio-only; schema.ts likewise). The wire schema for live-share is intentionally loose (`z.record(z.unknown())`) for complex bodies and defers strict re-validation to the impl layer.
- Bun's directory discovery STILL skips `*.it.ts` from `bun test apps/.../foo.it.ts` (the basename test), but `bun test ./apps/.../foo.it.ts` with a leading `./` treats it as an explicit path and runs it. The repo-level `test:it:bun` script globs `./apps/studio/integration/*.it.ts` and doesn't accept a name filter — run individual `.it.ts` files via `bun test ./path/to/file.it.ts` from the repo root instead.
- The repo-level `test:it:bun` script is at the ROOT package.json (`./apps/studio/integration/*.it.ts`), NOT under `apps/studio/`. Don't `cd apps/studio && bun run test:it:bun` — it will fail with "Script not found".

  - The hook-shim test pattern's `useMemo: (fn) => fn()` means new `useMemo` calls execute every render in tests — no slot ordering to worry about, unlike `useState` which is index-sensitive. Free to add new `useMemo` anywhere.

  - The AC's "reuses the existing body schemas" wording conflicts with the byte-for-byte mirror requirement (operations.ts imports don't resolve in the viewer repo).
