- Canvas renderer hook-shim test pattern: every node's test file copies the `renderWithHooks` + `findElement` walker from `image-node.test.tsx`. The shim provides synchronous useState/useRef/useEffect so the memoized impl can be called as a plain function; assertions then walk the returned React tree by `data-testid` or `el.type === <LucideIcon>`. Use this pattern for every new node type — DOM-mounted tests would need a full ReactFlow store.
- Biome a11y rules block a `<div onClick>` on the canvas. Use `<button type="button">` for click-bearing elements OR add `role="button"` + `tabIndex={0}` + `onKeyDown`. Nested buttons are invalid — make the body button and any overlay (edit/etc.) sibling absolute-positioned wrappers.
- Biome's `useSemanticElements` + `useFocusableInteractive` rules block `role="listbox"` on a non-`<ul>` wrapper AND `role="option"` on a non-`<li>` element (incl. `<button>`). The clean shape that lints + still functions as a combobox listbox is: scrollable `<div>` wrapper (no role) containing clickable `<button>` rows (no role/aria-selected). Drive the active-row signal via `aria-activedescendant={rowDomId}` on the search input + `data-selected={isSelected}` for styling. The command-palette in apps/web is the in-tree precedent. If you DO want strict listbox/option semantics, the only lint-clean path is `<ul>` + `<li>` (each with the role attr) but those can't be the direct click target — you'd need to nest a button, which then conflicts with `<li role="option">` having a focusable descendant. Not worth the gymnastics.
- Bun's `expect(value).toBe(false)` / `.toEqual({...})` will fail typecheck with "Argument of type 'false' is not assignable to parameter of type 'null'" when `value`'s declared type is a union including `null` (e.g. `let openChange: boolean | null = null;`). The overload resolver narrows to the `null` overload first. Workaround: declare the captured variable as `unknown` (`let openChange: unknown = null`) — the union narrows out and toBe/toEqual accept any expected value. Applies to ALL hook-shim test files that capture callback arguments through a closure-mutated variable.
- Adding a new patchable `data.<field>` (server PATCH body → mergeNodeUpdates) has a four-file cascade:
  - `apps/studio/src/operations.ts` — append the field to `NodePatchBodySchema` (use `.nullable().optional()` if the studio should treat `null` as the disk-strip / clear signal) AND add it to `NODE_DATA_PATCH_KEYS`.
  - `packages/canvas/src/adapter/types.ts` — append the field to `NodePatch` so host callers can pass it through `adapter.updateNode(id, patch)` with strict types.
  - `packages/canvas/src/history/wrap-adapter.ts` — if the field's "unset" state is meaningful (i.e. undo of a first-time set must clear it), add it to `NULL_CLEARS_NODE_KEY`. Without this, undo PATCHes `{field: undefined}`, JSON drops it, the server sees no key, and undo silently no-ops.
  - `make sync-seeflow-schema` — the vendored skill copy of schema.ts MUST be re-synced when schema.ts changes; CI fails on `make verify-seeflow-schema-sync` otherwise.
  - Tests to extend: `apps/studio/src/operations.test.ts` (NodePatchBodySchema parse + mergeNodeUpdates write/clear) and `packages/canvas/src/history/wrap-adapter.test.ts` (the null-clear undo path — copy the borderColor null pattern).
- Runtime callback injection into node data (host → renderer): the canvas's `nodes` prop carries on-disk FlowNode shape; the renderer reads runtime-only callbacks (e.g. linkflow's `onOpenPicker`) by intersecting `Record<string, unknown>` onto its NodeData type. Host injects them via a memo over `visibleNodes` that produces `{ ...n, data: { ...n.data, onCallback: bound } }` and casts the result as FlowNode. The bare host callback is wrapped in `useCallback([])` for cross-render stability, but the per-node bind/closure re-allocates on every memo run — that's fine because the memo only re-runs when `visibleNodes` itself changes, which is when the node identity already churned anyway. Same pattern fits any "host-owned UI state + canvas-owned node renderer" seam (image-node's `projectId` is the precedent).
- Bun's `mock.module(specifier, factory)` is PROCESS-GLOBAL — once a test file installs a module mock, every other test file in the same `bun test` run sees the mocked exports. There's no automatic per-file isolation and no clean unmock primitive. Mitigation: prefer stubbing the underlying side-effect (e.g. `globalThis.window` for navigation, `globalThis.fetch` for network) over `mock.module`-ing your own modules. If you must `mock.module`, scope the file to NOT import any other test that depends on the real module. project-switcher.test.tsx was clobbering use-navigate-flow.test.ts until we switched its navigation stubbing from `mock.module('@/hooks/use-navigate-flow')` to a fake `globalThis.window.history.pushState` recorder.
