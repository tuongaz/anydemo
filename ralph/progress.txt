# Ralph Progress Log — component-node-implementation (main)

## Codebase Patterns
- Bun workspaces: root `package.json` lists `apps/*` + `packages/*`. Cross-workspace deps use `"workspace:*"` (apps/studio → @seeflow/canvas) or `"file:../../packages/canvas"` (apps/web — already pinned that way). Both resolve as symlinks under the consuming app's `node_modules/`.
- Use `bun pm view <pkg> versions` (NOT `npm view`) before pinning third-party deps — PRDs may suggest version ranges that pre-date the actual package history.
- After modifying `package.json`, run `bun install` then `bun run typecheck` from repo root. `bun run typecheck` uses `--filter '*'` to typecheck every workspace.
- `bun run format` (biome write) then `bun run lint` (biome check) before commit, per CLAUDE.md.
- Biome's `organizeImports` enforces ALPHABETICAL named-import order — `{ COMPONENT_NAMES, componentCatalog }` (uppercase first), not insertion order. `bun run format` does NOT auto-fix this; only `bun run lint` flags it. Run lint before committing — format alone leaves named-import sort errors in place.
- The repo `bun test` output shows a `[registry] failed to load …` warning from `apps/studio/src/registry.test.ts` — this is an intentional malformed-JSON case, NOT a regression.
- @seeflow/canvas builds via `tsup` with multi-entry config (`{ index, catalog }`). Adding a new public-API subpath = (1) add entry to `tsup.config.ts`, (2) add the matching `"./<sub>"` block to `package.json` `exports`, (3) run `cd packages/canvas && bun run build:js`. `dist/` is in `.gitignore` — GHA commits it on `main` for external npm consumers; local dev resolves via the workspace symlink.
- `Record<K, V>` index access in canvas tests is treated as possibly-undefined under `noUncheckedIndexedAccess`. Pattern: pull the entry into a local, then `if (!entry) throw new Error('unreachable')` before chaining off it. Don't try `expect(entry).toBeDefined()` as a type guard — Bun's `expect` does not narrow.
- Adding a new `NodeType` enum member is a multi-file change: `Record<NodeType, …>` maps in `apps/studio/src/layout.ts` (`DEFAULT_DIMENSIONS`) and `apps/studio/src/operations.ts` (`SEMANTIC_KEYS_BY_TYPE`) MUST gain the new key or `bun run typecheck` fails. Grep for `Record<NodeType` / `Record<z.infer<typeof NodeTypeSchema>` before declaring schema-only changes "done". The matrix tests at the bottom of `schema.test.ts` use a hard-coded `ALL_TYPES` array (NOT the enum), so they don't need updates when adding a new type — though future stories may want to extend them.
- `ResolvedFlowSchema.superRefine` (apps/studio/src/schema.ts) is the cross-field validation seam — every per-node invariant that depends on inter-field state (image-path prefix, component catalog match, future spec/action cross-refs) lives there. Add new checks as a separate `resolved.nodes.forEach((node, idx) => …)` block inside the existing superRefine; keep error `path:` rooted at `['nodes', idx, 'data', …]` so the watcher's joined-issue-paths error message highlights the offending node.

## 2026-05-23 - US-005
- Created `apps/studio/src/component-spec-resolver.ts` exporting `inlineComponentSpecs(flow, projectRoot)` -> `{ flow, errors, refs }`. Iterates `flow.nodes` via `.map`; for every node where `node.type === 'component'` reads `<projectRoot>/nodes/<id>/spec.json`, JSON.parses, and returns a NEW node object `{ ...node, data: { ...node.data, spec: parsed } }`. Non-component nodes pass through by identity. `existsSync` miss + JSON parse failure each push a `SpecInlineError` with `path: 'nodes/<id>/data/spec'` (the path shape the watcher will surface in T-004 next story). `refs` collects every successfully-read project-root-relative path so the watcher can wire live-reload.
- Test file `apps/studio/src/component-spec-resolver.test.ts` covers 5 cases: attach happy-path, missing-file error path, malformed-JSON error path, non-component pass-through, and explicit non-mutation of the input flow + nodes.
- Plan reference: docs/plans/2026-05-23-component-node-implementation.md Phase 3 (Task 3.1 + 3.2). Followed the implementation verbatim but added the malformed-JSON and non-mutation tests on top of the plan's 3 to give the next story (US-006: `readMergedFlow` wiring) a stable invariant set.
- Files changed: `apps/studio/src/component-spec-resolver.ts` (new), `apps/studio/src/component-spec-resolver.test.ts` (new).
- Quality checks: `bun run typecheck` ✓, `bun run format` (no-op), `bun run lint` ✓, `bun test` ✓ (1718 pass / 1 skip / 0 fail — +5 new tests over US-004's 1713 baseline).
- **Learnings for future iterations:**
  - The `ResolvedFlow.nodes` array is a Zod discriminated union; `.map((node) => …)` narrows on `node.type !== 'component'` early-return, then the spread `{ ...node, data: { ...node.data, spec: parsed } }` needs a `as typeof node` cast because TS can't see that the structural addition keeps the discriminant tag stable. Followed the plan's `as ResolvedFlow` cast at the outer return for the same reason.
  - Tests that construct synthetic flows for the resolver need a `as unknown as ResolvedFlow` cast because the resolver's input is technically a `ResolvedFlow` but the upstream caller will feed it the post-mergeFlowAndStyle shape BEFORE spec inlining — so the test's component-node entries can legitimately carry a placeholder `data.spec` and the resolver overwrites it. Don't try to use the FlowSchema (on-disk) shape — the type signature is `ResolvedFlow` and changing it would ripple into US-006.
  - `noUncheckedIndexedAccess` flags `out.nodes[0]` as `T | undefined` in tests — narrow with `const first = out.nodes[0]; if (!first) throw new Error('unreachable')` (same pattern called out in the existing Codebase Patterns block for canvas tests; now confirmed to apply to studio tests as well).
  - The resolver intentionally surfaces a `SpecInlineError` array rather than throwing. US-006 will JOIN them with `;` into `readMergedFlow`'s `error` field and re-validate against `ResolvedFlowSchema` (so the catalog superRefine from US-004 runs against the inlined spec). Don't change the resolver to throw — the join + re-validate pattern is the whole point of separating concerns.
