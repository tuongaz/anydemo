## Codebase Patterns
- `apps/studio/src/share-*.ts` is the existing flat convention for live-share modules. Phase-7 SSE work introduces a `src/share/` subdirectory for new files — both styles coexist.
- StudioEvent + EventBus live at `apps/studio/src/events.ts`. Bridged SSE event types are the 5 starting with `flow:` or `node:` (NOT `file:changed` / `registry:reload`, which stay host-local).
- Envelope wire shape is centralized in `apps/studio/src/share-envelope.ts` (host) and `seeflow-viewer/src/lib/share-envelope.ts` (peer). Adding a new envelope `type` requires updating BOTH.
- Cross-repo schema parity is enforced with SYNC-WITH-PEER markers + a `scripts/check-*-sync.ts` script that normalizes whitespace+comments. The peer mirror lives in the sibling repo at `/Users/tuongaz/dev/seeflow-viewer/`; sync scripts must walk parent dirs to locate it and soft-pass when absent.
- Per-peer addressed broadcast pattern: peer-targeted frames use `broadcast(makeEnvelope(type, payload, { to: peerConnId }))` where peerConnId is `env.from` captured during presence/join (NOT the peerId — the relay routes on conn id). `to: 'all'` is reserved for fan-outs.
- Per-frame size cap pattern: when a wire frame must fit a byte cap, write a generic `chunk<T>(...): T[][]` over the natural partitioning unit (here per-flow), measure with `JSON.stringify({ wrapperShape }).length`, and stamp `{ chunk: 0..N-1, total: N }` only when N>1. Single-chunk frames omit the headers so the common path stays small.
- Bun directory test discovery skips `*.it.ts`. Use `bun test src/...` for unit + share tests; `bun run test:it:bun` for integration.
- `bun run format` must run BEFORE `bun run lint` (Biome).
- `apps/studio/src/watcher.test.ts` has pre-existing flaky fs-watching failures unrelated to share work — ignore in CI gating unless you touched watcher code.
- TypeScript narrows `let x: T | null = null` to `null` for the surrounding scope even when later writes happen inside injected callbacks. When testing schedule/cancel injection, capture the value via an object box (`const ref: { value: T | null } = { value: null }`) instead of a bare `let`.

- Learnings for future iterations:
  - The rate limiter assumes `now()` is monotonic. Tests freeze `now: () => 0` and inject a synchronous `schedule` (no-op cancel) to make burst behavior deterministic — letting wall-clock drift in even ~50ms refills 3 tokens and lifts the outbound count above the bucket ceiling.
  - The PRD test "200 frames in 50ms → ≤120 outbound" reads as "submitted within a 50ms window, measure within the window" — I freeze the clock during the burst so refills don't disguise saturation. Don't try to assert ≤burst across an interval that's long enough for the refill to add tokens.
  - `maxQueueDepth` defaults to `burst`. For tests that rely on multiple distinct queued non-terminal frames (e.g. asserting they DON'T coalesce), set `maxQueueDepth` explicitly above the expected queue length — otherwise the overflow rule drops them before you can observe queueDepth.
  - The tap defaults rate-limiting ON. Existing share.sse-bridge tests pass because the test setups never exceed burst within a single tick — but if you write a test that submits more than 120 events synchronously and asserts each emits, you must pass `rateLimit: false` or expect a queue.
  - Wiring is local to the tap; share.ts is untouched in this story. Backpressure (per-peer queues) and snapshot-on-resync are scheduled for US-072 and US-069 respectively.
  - When testing schedule/cancel injection, capture the callback via an object box (`const ref: { value: ... | null } = { value: null }`) — TS narrows `let pending: T | null = null` to `null` for the outer scope even when writes occur inside the closure.
