# @seeflow/canvas

Embeddable React Flow canvas. See `README.md` for the full public API.

## Rules

- **Public API:** `src/index.ts` only. Host apps must `import { ... } from '@seeflow/canvas'` — never deep-import from `packages/canvas/src/...`.
- **Internal imports:** relative paths (`'../lib/foo.ts'`). No `@/` aliases here — those belong to `apps/web`.
- **Peer deps** (`react`, `react-dom`, `@xyflow/react`, `lucide-react`, `react-markdown`, `remark-gfm`): the host provides them. Do not move them into `dependencies`. `react-markdown` + `remark-gfm` back the built-in sidebar's status section. `mermaid` is an **optional** peer dep used only by the DetailPanel's Detail-field renderer when the markdown contains a ` ```mermaid ` block; when the host doesn't install it, `MermaidBlock` falls back to a plain `<pre><code>`. The component dynamic-imports `mermaid` so it stays out of the canvas's static bundle (also listed in `tsup.config.ts:external`).
- **Tailwind v4:** package ships its own compiled CSS at `dist/style.css`. Internal classes use the v4 namespace prefix `sf:` (configured via `@import "tailwindcss" prefix(sf);` in `src/styles/index.css`); the codemod at `scripts/prefix-tailwind.mjs` keeps the source in sync. v4 emits classes in PREFIX-FIRST order: `sf:hover:bg-card`, `sf:data-[state=open]:animate-in`, `sf:-mx-1`, `sf:!opacity-100`. All non-utility globals (tokens, react-flow overrides, keyframes) live in `src/styles/index.css` scoped under `.seeflow-canvas-root` so the consumer's `:root` and global stylesheet stay untouched — the `@theme inline` form keeps Tailwind's `--color-*` vars OUT of the consumer's `:root` too. Keep class strings literal (no dynamic `sf:${var}` interpolation) so the build picks them up. Re-run `bun run --filter @seeflow/canvas build` after edits; the GitHub Action commits `dist/` on `main` for external consumers. Note: Biome 1.9.4 cannot parse v4 `prefix(sf)` syntax, so `src/styles/index.css` is in `biome.json` ignore.
- **Radix portals:** every Radix `Portal` in `src/ui/` and `src/components/` threads `container={useCanvasPortalContainer()}` so popovers/dropdowns/dialogs land INSIDE `.seeflow-canvas-root` and inherit the scoped CSS. New wrappers must do the same; otherwise their content gets portaled to `document.body` and loses the canvas's theme tokens.
- **Adapter seam:** edit mode requires a `CanvasAdapter` (`src/adapter/types.ts`). All mutations route through it — never call `fetch` from inside the canvas. Optional surface areas (e.g. `icons?: CanvasIconsAdapter`) keep their types — `PackSummary`, `InstallEvent`, `IconPackVendor`, `IconLicenseInfo` — local to the canvas. The studio's `apps/studio/src/icons/*` defines structurally identical mirror types but the canvas NEVER cross-imports; `apps/web` is the bridge that adapts wire JSON to the canvas-side type. If the wire shape changes, edit both sides in the same commit.
- **`wrapAdapterWithHistory` passthrough:** every optional `CanvasAdapter` field (currently `playAction`, `openFile`, `revealFile`, `computeLayout`, `icons`) must be forwarded in the wrapped-adapter spread at `src/history/wrap-adapter.ts` (`~line 502`). The pattern is `...(inner.foo ? { foo: inner.foo } : {})`. Skip this and the field is silently dropped before reaching `SeeflowCanvas` — type-check passes (`?` makes it optional) but the feature appears un-wired at runtime. Read-only or out-of-undo-scope sub-objects (e.g. `icons`) forward as-is; methods that should push undo entries need bespoke interceptor wrappers like the other top-level mutation methods.
- **Lucide component typing:** `lucide-react`'s `ForwardRefExoticComponent<LucideProps>` is NOT assignable to a hand-rolled `ComponentType<{ 'aria-hidden'?: boolean; className?: string }>` because its `propTypes['aria-hidden']` is `Validator<Booleanish>` (the string union `"true"|"false"`, not plain `boolean`). For any "Lucide component slot" type — discriminated-union member, registry value, adapter prop — use the imported `LucideIcon` type directly (that's what `src/lib/icon-registry.ts` already does for `ICON_REGISTRY: Record<string, LucideIcon>`).
- **Modes:** `mode: 'edit' | 'view' | 'mini'`. `edit` = full studio, adapter required. `view` = embedder read-only, chrome off but pan/zoom/Controls/selection on, adapter optional. `mini` = static thumbnail, every chrome affordance + every input path off, `autoFitView` defaults to `true`, adapter optional. Per-feature overrides on `CanvasFeatureOverrides` (incl. the mini-mode flags `showControls`, `showMiniMap`, `enableSelection`, `enableNodeMove`) compose on top of the mode preset — the resolver lives in `resolveFlags`.
- **Built-in sidebar:** `<SeeflowCanvas>` renders `<DetailPanel>` internally — driven by `selectedNodeIds[0]` / `selectedConnectorIds[0]`. Hosts pass `onNameChange` / `onDescriptionChange` / `onDetailChange` field-edit callbacks and a single `statusReport` for the selected node directly into the canvas. `disableSidebar={true}` suppresses it (custom inspector). `CanvasAdapter` does NOT expose its bound flowId — use the existing `projectId` prop for the sidebar's `flowId` lookup.
- **Auto-fit-view:** opt-in via `autoFitView?: boolean | { onMount?: boolean; onExternalNodeChange?: boolean }`. `undefined` / `false` → no auto-fit. `true` → fit on mount once nodes load AND fit when `autoFitViewSignal` bumps. Every internal fitView call (manual button, mount-fit, signal-fit, deferred flush) goes through the module-level `FIT_VIEW_OPTIONS` constant — never inline literals. The mount-fit fires from BOTH the `<ReactFlow>` `onInit` callback (primary path) AND a late-nodes `useEffect`; both serialize through `didMountFitRef` so the fit fires exactly once.
- **External-change fit (`autoFitViewSignal`):** host bumps a monotonic counter when an SSE / adapter update changes the node set. The signal-watching effect (deps: `[autoFitViewSignal]`) skips its first run via `signalEffectMountedRef` so it doesn't double-fire with the mount-fit. While a node drag (`draggingRef`) or resize (`resizingRef`) is in flight, the would-be fit is stashed in `pendingFitRef` and flushed by `flushPendingFit()` from `setResizing(false)` / `onNodeDragStop` / `onSelectionDragStop`. The flag itself (`onExternalNodeChange`) is read from `resolvedAutoFitViewRef` inside the effect — listing it in the deps array would cause spurious fits when the host flips the flag without bumping the signal.
- **Imperative ref handle:** `<SeeflowCanvas>` is a `forwardRef` component. Hosts pass `ref={useRef<SeeflowCanvasHandle>(null)}` to call `exportPdf()` / `exportPng()` / `openEmbedDialog()` / `capturePreview()` from a command palette, keyboard shortcut, or host-owned dialog (e.g. an Export-to-cloud preview thumbnail) without owning the underlying state. PNG / PDF capture lives in `src/hooks/use-canvas-export.ts` (jspdf is dynamic-imported on click); `capturePreview()` reuses the same fit-view + snapshot + restore path and returns the PNG dataUrl without triggering a download. The Embed dialog is mounted inside the top-right `ShareMenu`, so `openEmbedDialog()` is a no-op when `flags.showShareMenu` is off (mini mode or explicit `showShareMenu: false`). When extending the handle, add to BOTH `UseCanvasExportApi` and `SeeflowCanvasHandle`, wire via `useImperativeHandle` (deps array must include every function the returned object references), and update the US-014 imperative-handle test.
- **ShareMenu + chrome flags:** the top-right ShareMenu is gated on `flags.showShareMenu` (ON for edit + view, OFF for mini). The menu's `mode` is mapped `'mini' → 'view'` defensively. `<SeeflowCanvas>` owns `shareEmbedDialogOpen` state and threads `embedOpen` + `onEmbedOpenChange` into ShareMenu (controlled) so the imperative ref handle can flip the dialog without going through the menu click. ShareMenu still supports an uncontrolled fallback for standalone consumers. The Embed item is additionally gated on `flags.enableEmbed` (default OFF for every mode — opt-in via `enableEmbed={true}`); the existing edit-mode + `projectId` requirements still apply on top.
- **Hook-shim tests + useState placement:** the test suite uses a synchronous React dispatcher with `useStateOverrides[N]` indexed by useState DECLARATION order. When extending `SeeflowCanvas` with new internal state, ALWAYS append the `useState` call at the END of the body — never insert at the top — or every downstream test's slot reference silently shifts. Current order (14 slots): `connecting`, `dropPopover`, `drawStart`, `drawCurrent`, `contextMenuPos`, `contextOnNode`, `contextNodeType`, `contextEndpoint`, `rfNodes`, `spaceHeld`, `spaceDragging`, `shareEmbedDialogOpen`, `historyState`, `sidebarOpen`. The same rule applies to every other component with a dispatcher-shim test (`embed-dialog.test.tsx`, `icon-picker-popover.test.tsx`, etc.) — append-only at the END. The shim's stub setter is a no-op by default; to assert `setState(next)` intent (e.g. "this handler closes the sidebar"), pass a `setterSink: CapturedSetterCall[]` option to `renderWithHooks` / `callSeeflowCanvas` and inspect the captured `{ slot, next }` entries.
- **EmbedDialog `?theme=` (US-009):** the dialog builds `buildEmbedUrl(projectId, theme?)` where `theme` is `'light' | 'dark' | undefined`. The 3-option toggle stores a `themeChoice` of `'match' | 'light' | 'dark'`; `'match'` resolves at render time via `getResolvedThemeFromDocument(document)` — i.e. it reads `<html>` for the `.dark` class. Hosts that scope `.dark` to a non-document element should pick Light/Dark explicitly. When adding new "matches host theme" affordances elsewhere, reuse `getResolvedThemeFromDocument` from `src/lib/build-embed-snippet.ts` so the detection rule stays in one place.
- **Icon ids (`data.icon`) carry a vendor prefix:** `aws:lambda`, `gcp:cloud-run`, `azure:functions`, `iconify:logos:google-cloud`. Unprefixed names default to Lucide for backwards compatibility. Round-trip through `parseIconId` / `formatIconId` in `src/lib/icon-id.ts`; never split-and-rebuild ids by hand.
- **`IconRenderer` requires `studioBaseUrl`:** the `kind:'svg-url'` branch builds `${studioBaseUrl}/api/icons/${vendor}/${name}.svg`. `studioBaseUrl` flows through `CanvasStudioContext` (mounted by `SeeflowCanvas`); same-origin consumers leave it `''`. When adding new components that render icons, consume the context via `useCanvasStudio()` — don't accept a `studioBaseUrl` prop or hard-code `/api/icons/...`. For null/unknown ids, IconRenderer returns the `HelpCircle` placeholder inline (NOT wrapped in a sub-component) so `el.type === HelpCircle` identity assertions hold.
- **Picker → installs MUST go through `CanvasAdapter.icons.*`:** never call `fetch('/api/icons/...')` from inside the canvas. The adapter seam is the contract; `apps/web/src/...` (via `createRestAdapter` in `src/adapter/rest.ts`) is the only place that knows the wire format. `applyPackSummaries(packs)` from `src/lib/icon-registry.ts` is what populates the per-vendor tabs after a successful install — call it from the `done` SSE event in the install flow.
- **Optional peer-dep components (e.g. iconify):** module-singleton dynamic import + `.catch(() => null)` + `useState`/`useEffect` to surface the resolved module; renders a placeholder until loaded (or forever if the peer dep is missing). See `IconifyOrPlaceholder` in `src/components/icon-renderer.tsx`. Add the optional peer to `peerDependencies` + `peerDependenciesMeta.<name>.optional = true` + `devDependencies` + `tsup.config.ts:external` — forgetting `external` doubles the bundle size of `dist/index.js`.
- **Stable test/a11y attributes on edges:** the React Flow edge wrapper `<g class="react-flow__edge">` is owned by xyflow's sibling render path — JSX inside `EditableEdge` paints inside that `<g>` but can't directly modify its attributes. To attach a stable `data-*` to the wrapper (e.g. `data-handoff`, `data-edge-kind`), use the imperative pattern in `editable-edge.tsx`: a useEffect that does `document.querySelector('.react-flow__edge[data-id=<id>]')` + `setAttribute()` with a cleanup that calls `removeAttribute()`. Same shape every time.
- **Canvas-readiness signals:** for one-shot signals like `data-canvas-ready` (test bootstrap, a11y gating, etc.), set the attribute imperatively on the existing `wrapperRef.current` inside `<ReactFlow onInit>` — DO NOT add a new useState slot (would shift every hook-shim test's `useStateOverrides[N]` index per the rule above). `onInit` fires once after first layout, which is exactly the readiness moment Playwright + screen readers need.

## Workflow

- Tests live beside sources (`foo.ts` + `foo.test.ts`). Run `bun test` from the repo root.
- Typecheck: `cd packages/canvas && bun run typecheck`, or `bun run typecheck` from root for all workspaces.
- When adding a public export, add it to `src/index.ts` in the matching numbered section and keep the barrel sorted within the section.

## Component-node registry

- `src/registry/component-registry.tsx` maps every `COMPONENT_NAMES` entry (from `src/catalog/component-catalog.ts`) to a React impl consumed by `src/nodes/component-runtime.tsx`. Adding a new catalog entry REQUIRES adding a matching impl here — the module-level assertion at the bottom of `component-registry.tsx` throws on import if the two ever drift.
- Eager shadcn-styled primitives (Card, Separator, Tabs, …, Slider) live in `component-registry.tsx` itself. Reuse `src/ui/{button,slider,tabs}.tsx` when their API fits; otherwise build with plain HTML + `sf:*` Tailwind to avoid pulling in extra Radix packages just for the registry.
- Heavy/optional impls (Chart, Markdown, CodeBlock) ship as default-export `.tsx` files under `src/registry/impls/` and are loaded via `React.lazy(() => import('./impls/...'))`. Wrap each lazy with `<Suspense fallback={null}>` AT THE REGISTRY LAYER so `ComponentRuntime` doesn't need a Suspense boundary of its own.
- Optional peer deps (`recharts`, `shiki`) go in `peerDependencies` + `peerDependenciesMeta.<name>.optional = true` + `devDependencies` (for typecheck) + `tsup.config.ts:external` (so the bundler doesn't inline them). Forgetting the `external` entry will silently double the bundle size of `dist/index.js`.
- DO NOT try to import from `@json-render/shadcn`. It requires React 19 + zod 4; the canvas is locked to React 18 + zod 3 until the monorepo upgrades. Build shadcn-styled primitives in-house instead.
