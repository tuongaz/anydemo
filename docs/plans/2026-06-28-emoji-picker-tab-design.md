# Emoji tab in the Insert-Icon picker — Design

**Date:** 2026-06-28
**Status:** Approved (brainstormed)
**Scope:** `packages/canvas` only. No schema change, no new node type, no render-path change.

## Goal

Add an **Emoji** section to the Insert-Icon picker so users can drop emojis onto the
canvas the same way they drop icons.

## Key decision: emojis are iconify icons, not a new primitive

Emojis render through the **existing** `iconify` vendor as the Twemoji set. A picked
emoji stores the ordinary id `iconify:twemoji:1f600` in `node.data.icon` and paints via
the existing `IconRenderer` → `@iconify/react` path (same path the Logos tab already
uses). Therefore:

- **No** change to the Zod schema, `icon-id.ts`, `icon-resolve.ts`, or the
  insert/create/render pipeline.
- "Emoji" is a **picker-tab-only** concept.
- Delivery matches the existing Logos tab: glyph SVGs are fetched from the public
  iconify CDN (`api.iconify.design`), batched + localStorage-cached. Works in cloud
  (public CDN, no auth). The only gap is fully-airgapped installs — identical to the
  Logos tab today. Offline bundling (`@iconify-json/twemoji` via `addCollection`) is a
  clean follow-up if ever needed.

**Set chosen:** Twemoji — the most widely-recognized web emoji look, CC-BY, broad
coverage. iconify id form `twemoji:<codepoint>`.

## Architecture

### 1. Decouple "tab" from "vendor"

Today `activeTab: IconVendor` and `ICON_NAMES_BY_VENDOR[activeTab]` share one key. Emoji
ids are *also* `iconify` vendor (collides with the Logos tab), so introduce a
picker-only type:

```ts
type PickerTab = IconVendor | 'emoji';
```

A small resolver maps a tab → `{ names: string[]; renderVendor: IconVendor }`:

- every existing tab → `{ names: ICON_NAMES_BY_VENDOR[tab], renderVendor: tab }`
- `'emoji'` → `{ names: <catalog name-segments>, renderVendor: 'iconify' }`

The grid passes `renderVendor` to `renderVendorTile`, so an emoji tile formats to
`iconify:twemoji:1f600` through the existing `formatIconId` and emits that id on pick.

### 2. Emoji catalog (generated, committed)

`src/lib/emoji-catalog.ts` — an array ordered by emoji group:

```ts
interface EmojiCatalogEntry { id: string; label: string; keywords: string[] }
// id example: 'twemoji:1f600'  (the segment after `iconify:`)
```

Generated by `scripts/gen-emoji-catalog.ts` (Bun), which **joins emojibase metadata
with the actual `@iconify-json/twemoji` icon list** and emits only entries whose
computed `twemoji:<code>` id exists in that set — guaranteeing every tile resolves (no
broken glyphs). Ordering follows emojibase group + order. Coverage: full standard set,
**neutral skin tone only** (no modifier permutations) → ~1,900 browsable entries.

`emojibase-data` and `@iconify-json/twemoji` are **devDependencies only**; runtime ships
the generated file. The catalog is **lazy-loaded** (dynamic import) on first Emoji-tab
open so it stays out of the main `dist/index.js`.

## UI / UX (all inside `IconPickerBody`)

1. **Tab:** add `{ id: 'emoji', label: 'Emoji' }` to `TAB_DEFS` after Logos. Always
   enabled (like lucide/iconify); never a pack-install tab.
2. **Grid:** the existing hand-rolled virtualized 8-col grid renders the emoji tab
   unchanged — fed catalog names with `vendor: 'iconify'`. Category-ordered so scrolling
   flows Smileys → People → Animals → Food → … **No sticky category headers in v1**
   (flat-row windowing; headers = variable-height windowing, deferred).
3. **Search:** emoji "names" are codepoints, so the substring-on-name filter is useless.
   The Emoji tab matches the query against `label + keywords`; other tabs keep
   `filterIcons`. Placeholder → "Search emojis…" on the emoji tab.
4. **Recents:** `pushRecent` already records any picked id. Extend the Recents row
   (currently lucide-only) to also show on the Emoji tab, filtered to emoji ids.
5. **Reach:** because this lives in `IconPickerBody`, emojis appear both in the toolbar
   Insert-Icon flow and the DetailPanel icon-field editor (replace mode) — for free.

### Hook-shim slot rule

Any new `useState` is appended at the END of the component body. Plan: load the catalog
in `IconPickerPopover` as appended slot 8 (`emojiCatalog`) and pass it down, so
`IconPickerBody` keeps its single `scrollTop` slot.

## Testing (gate: unit + integration + e2e all green)

- **Unit:** catalog shape/order (every id parses, non-empty), the tab resolver, the
  emoji keyword filter (e.g. "happy" → `1f600`).
- **Picker:** extend `icon-picker-popover.test.tsx` — Emoji tab renders, picking emits
  `iconify:twemoji:…`, emoji recents show on the Emoji tab. Respect the slot rule.
- **E2E:** one Playwright test — open Insert-Icon → Emoji tab → grid visible. Build the
  web + mcp bundles first (e2e bundle-build gotcha).
- Rebuild `@seeflow/canvas` dist + dev CSS so it shows in the running dev server.

## Rollout

`packages/canvas` change in the OSS `seeflow` repo. Work in an isolated worktree, then
merge `feat/emoji-picker-tab` into `main` (local + remote). **Merging to main does not
auto-deploy cloud** — that needs the separate OSS release + lockstep `SEEFLOW_REF` bump.
Flagged, not done here unless requested.

## Out of scope (YAGNI)

- Sticky category headers / category jump-bar.
- Skin-tone modifier variants.
- Offline-bundled emoji SVGs.
- A new `emoji` wire vendor or node type.
